## 1. 背景与问题

本项目的核心链路是「业务问题 → 本体语义解析 → 元数据验证 → SQL 生成」。当前内置 `Ontology/aw_ontology.owl` 描述 AdventureWorks 销售域。切换领域需要手工准备文件和重启服务，缺少在线校验、恢复和生效状态展示，普通数据分析师也难以从零编写 OWL。

**现有代码事实与边界：**

- `OntologyService.load()` 按 `OntologyConfig.DIRECTORY/FILE_GLOB` 递归加载文件到独立 Owlready2 World，没有在线 reload。部分文件加载失败时仍可能成功返回，并通过 `load_errors` 报告；全部失败或没有匹配文件才抛错。激活必须增加严格检查。
- `close()` 会释放 World，不能在候选服务及 Agent 就绪前关闭旧实例。
- `PUT /config/mysql` 的配置锁、活跃查询检查和候选对象构建可供借鉴，但不等于可直接复用的多文件事务和进程中断恢复保证。
- OWL 是业务语义权威，数据库元数据是物理结构与权限权威。显式映射仍须在 SQL 生成前验证。
- 仓库 OWL 默认只读；管理入口操作独立工作副本和发布快照，不覆盖或格式化原始种子文件。

## 2. 目标、非目标与支持范围

### 2.1 目标

1. 在 Web 中完成上传、查看、编辑、校验、启停、备份恢复和显式热激活。
2. 分离工作副本与发布版本，保存后重启也不能绕过激活。
3. 激活提交前失败保留旧服务与会话；成功后统一切换并同步前端。
4. 保护内置资产，允许停用和重新启用。
5. P1 从 MySQL 结构确定性生成可审阅草稿，降低编写门槛。

### 2.2 非目标与范围

| 项 | 本期边界 |
|----|----------|
| 图形编辑 | P2；本期采用 RDF/XML 文本编辑 |
| 完整版本历史 | 不提供任意历史浏览和回滚；保留单文件上一版备份、当前发布快照及事务恢复必需的上一发布快照 |
| 多用户与鉴权 | 仅支持受信任的单用户环境；管理接口不得无鉴权暴露公网，远程访问由部署层提供访问控制 |
| 多实例 | 单进程、单 worker；进程内锁不提供多实例一致性 |
| 推理机管理 | 环境变量控制，默认关闭，不提供 UI 开关 |
| AI 语义生成 | P1 不调用 LLM；语义润色、指标定义和业务增强列入 P2，不使用“AI 生成”产品表述 |
| 数据源 | P0 管理与数据源无关；P1 结构生成仅支持 MySQL，Databricks 下展示不支持原因 |

## 3. 用户、场景与状态模型

### 3.1 用户故事

目标用户为受信任单用户部署下的数据分析师与演示维护者。

| 编号 | 用户故事 | 优先级 |
|------|----------|--------|
| US-1 | 上传外部编写的 OWL，保存前取得校验报告 | P0 |
| US-2 | 区分工作副本、待激活变更、当前发布版本与加载健康度 | P0 |
| US-3 | 在线修改本体，保留可恢复的上一版 | P0 |
| US-4 | 删除文件并从已删除列表恢复 | P0 |
| US-5 | 停用或启用文件，包括内置本体 | P0 |
| US-6 | 等待查询结束后显式激活整个工作集，失败时继续使用旧版 | P0 |
| US-7 | 从 MySQL 勾选表生成草稿，审阅、保存并激活 | P1 |
| US-8 | 下载工作副本或发布版本，在外部工具编辑 | P0 |

典型流程：连接 MySQL → 选表生成草稿 → 审阅修订 → 校验并保存工作副本 → 查看整批差异 → 确认激活。

### 3.2 状态与版本

| 对象 | 含义 | 生效规则 |
|------|------|----------|
| 内存草稿 | 尚未保存的编辑、上传预览或生成结果 | 不参与查询，关闭页面可能丢失 |
| 工作副本 | 已保存的文件及启用状态 | 不自动生效，允许存在待解决的跨文件依赖问题 |
| 已发布快照 | 成功激活的完整启用文件集、依赖及摘要 | 查询和重启只使用它 |
| 单槽备份 | 文件上一次成功编辑、覆盖或删除前的内容与启用状态 | 恢复仅写入工作副本 |

- `workspace_revision` 标识整个工作集，每个文件还有独立 `revision`。写入需携带预期版本，在锁内校验；缺失返回 428，过期返回 409。
- `active_revision` 标识当前发布快照，记录来源工作集版本、内容摘要、激活时间及校验摘要。待激活差异按内容和启用集合比较，不能只比较版本计数。
- 文件分别展示存在/已删除、启用/停用、受保护、有备份、新增/修改/删除/启停待激活。运行时 health 与工作副本校验状态分开。
- 允许工作集暂时没有启用文件，以支持替换唯一旧本体；后端禁止发布空启用集，旧发布版本继续服务。首次没有可用发布版本时允许应用以 metadata-only 启动并报告本体不可用。

## 4. 功能需求

### 4.1 P0：管理闭环

#### FR-1 列表与状态

展示稳定文件 ID、名称/原始相对路径、大小、修改时间、启用状态、保护状态、备份状态、revision 和待激活差异。提供“已删除且可恢复”筛选。

整体展示工作集版本、发布版本、最后激活时间、整批差异以及运行时健康度。`OntologyService.health()` 仅描述实际生效实例，不代表磁盘工作副本已加载。

#### FR-2 查看与下载

支持查看和下载工作副本、当前发布内容和单槽备份，明确来源版本；不存在返回 404。下载由服务端返回附件名和原内容。

P0 在线编辑限定 UTF-8 RDF/XML。迁移遇到其他格式不得静默重写，须报告不支持原因。

#### FR-3 上传与覆盖

- multipart 上传，先检查原始字节限额，再严格 UTF-8 解码和文件语法校验，最后提交工作副本；失败不改变已提交正文、备份或 manifest。
- 新文件名称满足 `^[A-Za-z0-9][A-Za-z0-9_.-]{0,120}\.owl$`，额外拒绝 `..`、路径分隔符、Windows 保留名。按大小写不敏感规则检查冲突，保持跨平台一致。
- 同名默认 409。显式覆盖需目标 ID、overwrite 和预期版本，保持原启用状态；不能用名称绕过保护或覆盖停用文件。
- 新上传默认停用，用户启用后显式激活。语法失败禁止保存；跨文件问题在报告中展示并在发布时阻断，支持分次上传依赖文件。

#### FR-4 编辑与保护

保存顺序：校验内容 → 锁内核对预期版本 → 准备正文、备份和 manifest → 事务提交。成功才轮转备份和递增版本，失败保持已提交状态一致。

受保护文件禁止编辑、删除、上传覆盖和恢复写入，返回 403；允许查看、下载和启停。保护依据种子身份及受控元数据，不仅匹配文件名；大小写变体、停用状态和同名上传不能绕过。

#### FR-5 删除

仅非保护文件可删除，操作前确认。删除保存当前内容及启用状态到单槽备份，在工作集中保留 tombstone，已发布快照不变。重复删除返回 409，不覆盖备份；已删除列表提供恢复入口。

#### FR-6 启用与停用

启用状态存于工作集 manifest，不通过 `.disabled` 改名实现。API 接收明确的目标 `enabled` 值，避免重试 toggle 反转操作。启停不轮转内容备份、不修改当前发布版本。

允许空工作集保存，但后端拒绝空发布集；UI 提示用户先上传/启用替代文件再激活。

#### FR-7 分层校验

返回 `{scope, valid, ontology_iri, class_count, property_count, individual_count, checks[], errors[], warnings[]}`。问题包含稳定 code、严重性、文件/实体定位及消息。

| 层级 | 要求 |
|------|------|
| 输入 | 原始字节限额、总量、UTF-8、格式、路径和 XML 安全策略 |
| 文件语法 | 隔离解析环境；成功与失败都释放 scratch World；解析前禁止自动解析外部资源 |
| 依赖和合并 | 按候选启用集检查 imports、IRI 与缺失依赖；覆盖时移除目标旧版本，避免与自身旧内容冲突 |
| 运行时加载 | 完整候选服务能建立索引且 load_errors 为空，空集拒绝 |
| 物理映射 | 可选报告元数据验证结果/未执行原因；不替代 SQL 前的物理验证 |
| 逻辑一致性 | 默认 not_checked；仅配置开启推理时检查，失败或超时阻止激活；关闭时不得宣称一致性已证明 |

- `valid` 仅表示所选 scope 的必需检查通过；文件可保存不等于整批可发布。
- P0 imports 仅允许候选集内显式 IRI → 文件映射，禁止联网或加载管理目录外文件。单文件校验提示缺失依赖，发布校验将其作为 error；循环依赖须有界处理。
- 共享实体引用允许；重复实体定义 warning；多个文件声明同一本体 IRI、冲突实体种类定义为 error。激活确认展示警告。
- 禁止 DTD、外部实体和任意本地/远程资源解析。解析器行为通过安全测试验证，不能仅依赖 ONLY_LOCAL。

#### FR-8 备份与恢复

每次成功编辑、覆盖、删除保留恰好一个操作前内容和启用状态，附摘要与时间。受保护文件不维护可变内容备份。

恢复前重新校验。目标存在时与备份交换内容及启用状态，恢复前的版本成为新备份；目标已删除时恢复备份中的内容和启用状态，并保留该备份。缺失、损坏和版本冲突分别报告。

**恢复只更新工作副本，不自动激活。** 用户随后激活的是整个启用集，确认页必须包含其他待激活修改。

#### FR-9 显式热激活

1. 用户审阅整批差异、警告及清空所有现有会话的影响，提交预期 workspace/active revision。
2. 获取与 MySQL 切换、聊天 run 注册共用的 configuration_lock；存在未完成查询返回 409。锁内重新核对版本，阻止并行写入和新查询注册。
3. 从固定工作集构建不可变候选快照，执行严格发布校验；不得扫描包含工作副本、备份和历史发布的父目录。
4. 保留旧 World、Master 和会话，构建完整候选 OntologyAgent、DataInsightAgent、MasterAgent 及所需 Metadata 依赖，完成初始化检查。失败仅销毁候选。
5. 按第 6 节协议提交发布指针并安装候选运行时和状态；关键内存切换段无 await、外部 I/O 或临时资源构建，对外不可见中间态。
6. 仅成功提交后失效旧会话、历史和响应缓存，返回新版本和 sessions_reset=true；随后释放旧资源，不关闭新实例仍共享的数据源。
7. 提交前失败保留旧运行时和会话，工作副本继续保留供修正；提交后清理失败只告警，不将成功激活误报为回滚失败。

没有实际差异时返回 changed=false，不重建、不清会话。客户端超时/断连后应查询版本确认结果；提交前取消清理候选，已提交操作不得因请求取消而回滚。

### 4.2 P1：从 MySQL 结构生成草稿

#### FR-10 生成范围与映射

仅读取当前 MySQL allowlist 内的表、列、注释和外键，不读取业务行。复用 list_tables/get_table，增加受 scope 约束的外键查询，保持公共数据源协议兼容。

表清单使用完整 database.table，生成携带不含凭据的数据源身份/配置版本；生成与保存时检测来源变化，变化后要求重新生成，防止误绑定到新连接。P1 支持基础表，视图明确标记不支持。限额内选择表，超限拒绝而不截断。

| 对象 | 映射与限制 |
|------|------------|
| 表 | owl:Class；保留表名 label，非空注释作为补充 label/comment |
| 列 | owl:DatatypeProperty，domain 为所属类，保留列名、注释、原始 SQL 类型 |
| 常见类型 | int→xsd:integer、decimal→xsd:decimal、varchar/text→xsd:string、date→xsd:date、datetime→xsd:dateTime |
| 特殊类型 | unsigned 保留约束注解；enum/JSON 使用字符串并标注类型；binary/blob→xsd:base64Binary；MySQL time 不强行视为日内时间，以字符串和 warning 表达；未知类型退化字符串并警告；timestamp 不推断时区 |
| 外键 | ObjectProperty 保存约束身份、有序源列/目标列对及 domain/range，覆盖复合外键、自引用和同表间多个外键 |
| 物理映射 | 类 sourceTable=database.table；列属性同时携带所属 sourceTable 和精确 sourceColumn |

引用未选中表的外键不生成可用关系，不自动扩大范围；报告遗漏关系和目标。外键注解格式与服务读取适配一起实现和测试，只有 domain/range 不构成可执行 join。不得无依据地将可空性、唯一性或外键升级为业务基数、公理和指标。

显式映射减少名称猜测；get_schema_mapping() 的高置信度只表示注解存在。生成 SQL 前 MetadataAgent 仍验证表列、权限和 scope，覆盖换库、删表、改列名和 allowlist 收紧场景。

#### FR-11 草稿身份与质量

- 默认 namespace 为 `urn:oda:ontology:<uuid>#`；不同生成请求唯一，同一草稿编辑保存保持稳定。自定义 namespace 检查合法性与冲突。
- 实体 IRI 包含数据库/表/列或约束作用域，不使用裸 id/name。中文、特殊字符进行稳定编码，检测并消解编码碰撞，注解保留原始物理名称。
- 正确转义并序列化为 RDF/XML，标注 `SCHEMA DRAFT — requires human review`、来源、生成时间及选表范围，不含凭据。
- 结果先保存在内存，返回覆盖计数、遗漏项和 warnings，经审阅保存走正常工作副本流程，永不自动启用或激活。
- 质量要求除可解析外，还包括选中表列完整、IRI 无意外合并、映射可回查、外键列对正确；不支持项必须提示。

### 4.3 P2（不承诺）

图形编辑、多版本历史与 diff、多用户权限、多实例一致性、Databricks 结构生成、LLM 语义增强、模板市场及 UI 推理机管理。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 并发 | 写入、激活、数据源切换共用锁；活跃查询时写入 409；读取/独立校验可并行但读取一致版本；版本前置条件防止多标签页丢失更新 |
| 安全 | 受信任部署、禁外部解析、路径/资源限制；本体和数据库注释为数据，不能绕过提示词及工具安全约束 |
| 可靠性 | 工作集正文/备份/manifest 一致提交；启动只认发布指针，不把草稿猜测为发布状态 |
| 路径 | 规范化后必须位于受管根内；P0 拒绝受管路径中的符号链接/junction，不能只检查文件名 |
| Windows | 同卷暂存、句柄关闭后替换；os.replace 只保证单个替换，不代表多文件原子事务 |
| 性能 | 内置本体规模、推理关闭、无外部调用时，上传处理＋保存校验＋激活服务端累计目标 ≤10 s，不含用户审阅；记录硬件、文件/字节数和阶段耗时 |
| 预算 | 默认单文件 5 MiB、现存文件 100 个、正文共 50 MiB、生成最多 50 表/2000 列；校验与激活各 30 s，推理包含在激活预算中 |
| 执行隔离 | 阻塞解析不能进入 async 事件循环；超时必须终止受控执行单元或协作取消，不能仅停止等待线程；超时任务不能后续提交 |
| 可观测 | UI 显示阶段、operation ID 和终态；日志记录版本、结果、耗时，不记录完整本体、凭据或查询行；错误不泄露本地绝对路径 |

限额进入 settings.py、.env.example 和测试，manifest 不保存安全配置。备份和发布快照另设磁盘总配额并预留候选空间，不足时显式失败，不能删除当前与恢复必需版本。具体配置名、磁盘配额默认值和终止执行方案在 M1 实现设计中确定。

## 6. 技术方案概要

### 6.1 存储、兼容与迁移

原 DIRECTORY/FILE_GLOB 仅作为首次导入的种子来源，管理存储默认独立放入 `data/ontology-management/`（运行数据不提交），禁止位于种子 glob 扫描树中。

```text
Ontology/                         # 原种子，只读，保留原子目录
data/ontology-management/         # 独立受管目录
├── workspace-current.json        # 已提交工作集指针
├── workspaces/<generation>/      # 不可变正文、单槽备份、tombstone、manifest
├── releases/<revision>/          # 不可变启用集、依赖与摘要
├── active.json                   # 当前/上一发布指针与元数据
└── staging/                      # 未提交候选
```

- 文件用稳定 opaque ID，显示原始相对路径；子目录同名文件保持独立身份。ID/客户端路径不得直接成为文件系统路径。
- 首次导入按现有配置列举文件，校验格式、保护身份、路径和完整加载能力。严格通过后事务创建初始工作集及发布版本；这是唯一无需点击激活的种子引导。
- 迁移失败不改种子、不发布部分集合，以 metadata-only 启动并给出修复报告。不支持格式、自定义 glob 匹配非本体或名称冲突不能静默丢弃/转换。
- 引导完成后只从 active.json 启动；修改种子或重启不触发重新导入。已有存储损坏不能当作首次初始化。
- manifest 保存 ID、逻辑路径、版本、摘要、启用/保护状态和备份索引。损坏或摘要不符时拒绝相关写入/发布，保留可用运行时；重启恢复最后完整发布，无法恢复则 metadata-only，不能加载草稿。

### 6.2 提交与失败矩阵

工作副本操作先构建完整新 generation，包含正文、备份与 manifest，验证并持久化后原子替换 workspace-current.json。指针替换前失败不改变旧工作集，替换后视为已提交。内部暂存不构成面向用户的历史版本功能。

激活先持久化完整 release，候选 World/Agent 就绪后提交 active.json，再在配置锁内无异步让出地安装准备好的运行时引用和空会话容器。保留旧引用用于异常恢复；无法恢复指针与内存一致性时阻断查询，不能继续提供不一致服务。

| 失败位置 | 规定结果 |
|----------|----------|
| 校验、加载、候选 Agent 构建 | 释放候选，旧发布/会话/缓存不变，保留工作副本供修正 |
| 正文、备份、manifest 暂存 | 工作集指针不变，清理未提交暂存 |
| 发布持久化或 active 提交前 | 旧发布与运行时不变，返回存储错误 |
| active 提交后、内存安装前进程退出 | 重启从指针加载完整新 release，不加载草稿 |
| 活进程内安装异常 | 恢复旧指针、引用与会话；恢复失败阻断查询，报告恢复中 |
| 提交后旧资源清理失败 | 新版本继续服务，激活仍成功；告警并有界重试清理 |
| 客户端超时或断连 | 按提交边界取消或完成；客户端查询版本确认，不盲目重试 |

启动核对指针和摘要、恢复并清理未提交暂存；保留当前与恢复必需的上一发布快照，对其余旧 generation/release 有界回收。保证覆盖应用异常与进程中断；断电持久性依赖文件系统及同步写入能力，必须说明实际验证范围。

### 6.3 后端 API

新增 store.py（版本、事务、备份）、validation.py（分层校验）、generator.py（P1）。候选 Agent 构建提取为无全局提交副作用的工厂，由激活协调器提交。同步检查 startup、health、错误恢复及 MySQL 切换后的本体引用。

| 方法 | 路径 | 说明 | 优先级 |
|------|------|------|--------|
| GET | `/ontology/files` | 文件/删除项、版本、差异、运行时 health | P0 |
| POST | `/ontology/files` | multipart 上传/显式覆盖，携带预期版本 | P0 |
| GET | `/ontology/files/{file_id}` | version=workspace/active；download=1 下载 | P0 |
| PUT | `/ontology/files/{file_id}` | 保存正文与预期版本 | P0 |
| DELETE | `/ontology/files/{file_id}` | 删除并保留可恢复项 | P0 |
| POST | `/ontology/validate` | 校验未保存内容或工作集，返回分层报告 | P0 |
| PUT | `/ontology/files/{file_id}/enabled` | 指定目标 enabled | P0 |
| GET | `/ontology/files/{file_id}/backup` | 备份内容/元数据及下载 | P0 |
| POST | `/ontology/files/{file_id}/restore` | 仅恢复工作副本 | P0 |
| POST | `/ontology/activate` | 核对 workspace/active 预期版本并整批发布 | P0 |
| GET | `/ontology/generate-draft/tables` | MySQL 表清单与来源版本 | P1 |
| POST | `/ontology/generate-draft` | tables、可选 namespace、source_revision → 草稿与报告 | P1 |

- 错误采用 `detail={code,message,issues?,current_revision?}`：403 保护限制，404 不存在，409 活跃查询/版本冲突/空发布集，413 超限，422 内容无效，428 缺版本条件，503 存储不可用/恢复中，504 超时。
- 独立校验对合法请求返回 200 和 valid=false 报告；保存/激活被校验阻止返回 422 及相同报告。DELETE 的预期版本使用请求头，不依赖请求体；其他写入在 schema 中声明版本字段。
- 激活返回 active_revision、workspace_revision、changed、sessions_reset 和清理 warnings。无差异重试不能重复清空会话。
- 管理进度使用独立操作状态或管理事件通道，不改变聊天 SSE 类型；M1 交付 operation ID、阶段状态和终态查询，传输协议在实现设计中落实。
- Pydantic 模型同步前端 types、API 客户端和 HTTP 契约测试。

### 6.4 前端与会话同步

新增 OntologyManagerModal.tsx，沿用设置弹窗 busy、错误处理与布局。左侧文件及已删除筛选，右侧查看/编辑、校验、结构草稿；显示发布版本、激活时间和待激活差异。

激活确认包含整批差异与所有会话清空影响；恢复明确提示只修改工作副本。冲突保留本地编辑文本，让用户刷新比较，不自动覆盖。受保护入口隐藏，后端仍强制保护。

FormData 由浏览器生成 multipart boundary，不能沿用全局 JSON Content-Type。

成功激活同步清理前端失效 thread、消息、历史及缓存状态并进入新会话；同源标签页通知配合窗口聚焦时版本检查。未收到通知的旧页面须由服务端识别版本/会话失效并返回可消费错误，不能默默混用旧上下文。若增加聊天请求版本字段，同步 API、类型与流式测试，保持现有 SSE 类型不变。

### 6.5 测试策略

- store 单元测试：版本冲突、路径/保护、备份交换、删除恢复、事务失败和启动恢复。
- validation 测试：分层结果、imports、IRI、覆盖排除旧版本、XML 安全、资源预算与释放。
- API：handler 测试之外加入真实 ASGI HTTP 请求，覆盖 multipart、参数、下载头、状态码、序列化与脱敏。
- 激活：真实候选 World、部分 load_errors、Agent 初始化失败、指针故障、进程中断恢复、聊天竞争、MySQL 切换、清理失败。
- 生成：离线 fixture 覆盖同名列、中文/特殊字符、复合/自引用外键、未选中目标、类型降级、来源变化及 scope。
- 前端：管理流程、多标签页失效，执行 lint/build。测试使用临时目录，不改种子 OWL、不读取业务行；外部 MySQL/Docker 和性能测试如实报告环境及 skip。

## 8. 验收标准

| 编号 | 标准 |
|------|------|
| AC-1 | 畸形/非 UTF-8 返回 422，正文、备份、manifest 已提交状态不变；超限 413 |
| AC-2 | 保存未激活后重启仍加载旧发布内容，工作副本差异保留 |
| AC-3 | 候选加载成功但 Agent 构建失败，旧 World/Agent/会话/缓存可用 |
| AC-4 | 任一文件 load_errors 或空启用集拒绝整批发布 |
| AC-5 | 查询期间写操作 409；激活与聊天竞争不混用新旧版本 |
| AC-6 | 保护覆盖编辑/删除/上传覆盖/恢复及大小写、停用绕过；查看/下载/启停正常 |
| AC-7 | 成功编辑/覆盖/删除仅保留单槽备份，删除项可恢复，内容与启用状态恢复正确 |
| AC-8 | 恢复不自动发布任何待激活修改，后续激活展示整批差异 |
| AC-9 | 多标签页过期写入 409、不覆盖；缺前置条件 428 |
| AC-10 | 正文/备份/manifest/发布指针故障及中断后恢复到完整已提交状态，不加载暂存或草稿 |
| AC-11 | 提交后清理失败新版本可用并告警；提交恢复失败阻断查询、不假报成功 |
| AC-12 | 成功激活前后端及其他标签页会话失效；无差异激活不清会话 |
| AC-13 | 越界 imports、DTD/外部实体、路径穿越、链接/junction 被拒绝；超时任务不能继续提交 |
| AC-14 | 共享引用不误报重复定义，重复本体 IRI 阻断，覆盖自身无旧版本冲突 |
| AC-15 | 兼容原目录配置/子目录；不支持格式和 manifest 损坏明确报告，不重导入或猜测发布状态 |
| AC-16 | 按第 5 节口径验证 ≤10 s 并记录环境；关闭推理时显示逻辑一致性未检查 |
| AC-17 | P1 草稿 RDF/XML 合法、带 DRAFT 和显式映射，选中表列完整且不静默截断 |
| AC-18 | P1 同名列/特殊字符/多次生成无意外 IRI 合并，复合及自引用外键列对准确，遗漏关系有 warning |
| AC-19 | P1 禁止越 allowlist；换库/删表/改列/收紧权限后 SQL 前仍验证，不信任旧映射高置信度 |
| AC-20 | 实际 HTTP 覆盖 multipart/下载/错误/版本参数；前端 lint/build 通过，外部测试如实报告 |

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 草稿与运行时混淆 | 工作集/发布隔离，启动只读发布指针，UI 双状态 |
| 半更新及进程中断 | 不可变 generation/release、单指针提交、摘要与恢复测试 |
| IRI 合并/依赖缺失 | 分级校验、重复本体阻断、固定候选集 imports |
| 全部停用 | 后端拒绝空发布，保留旧版；无发布版本时 metadata-only |
| 解析/推理耗尽资源 | 大小/总量/时间预算、可终止执行，默认不推理 |
| 清会话造成困惑 | 整批确认、前后端同步、其他标签页版本检测 |
| 旧编辑覆盖 | 版本前置条件，保留本地文本，不采用后写胜出 |
| 映射误当物理事实 | 来源和 warnings，SQL 前持续 Metadata 验证 |
| 未授权管理访问 | 限定受信任部署，部署层访问控制；延期鉴权不代表支持公开部署 |
| 运行数据持续增长 | 独立磁盘配额、有界回收，保留当前及恢复必需版本 |
